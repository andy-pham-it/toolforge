# SDLC Agent Flows — Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Phase 1 of the SDLC Agent Flows system — single npm package `@andy-toolforge/sdlc-workflows` with 7 skill files, 3 plugin MCP tools (auto-discovered by `@andy-toolforge/mcp`), template files, and all project scaffolding flows.

**Architecture:** Single CommonJS package using npm workspaces. No separate MCP server — 3 template-serving tools live in `mcp-tools.js` (plugin format), auto-discovered by `@andy-toolforge/mcp`. `postinstall.js` uses `installSkills()` from core and generates a version manifest. Skill files reference MCP tools (`sdlc_get_template`, etc.) with inline markdown fallback. Templates are Agile-only Phase 1 (IEEE/ISO as reference notes in SKILL.md). Optional Learn step in every skill workflow.

**Tech Stack:** CommonJS (per Toolforge convention), `@andy-toolforge/core` for `installSkills()`, `@andy-toolforge/mcp` for plugin tool discovery.

## Global Constraints

- All code uses CommonJS (`require`/`module.exports`) — no ESM, no TypeScript, no Bun
- `@andy-toolforge/core` is the only allowed dependency for `sdlc-workflows`
- MCP tools are plugin tools in `mcp-tools.js` — not a separate MCP server
- Tool signature: `{ definition: { name, description, inputSchema }, handler: async (llm, args) => result }`, exported as array
- Skill files are plain Markdown (.md) — no JS/TS in skills/
- Templates are Agile-only Phase 1 (agile-scrum, agile-prd, itil-sre, itil-runbook, sre-runbook)
- Manifest auto-generated by postinstall.js (not glob-based) — version manifest in `.opencode/manifests/sdlc-workflows.json`
- Output path for SDLC docs: configurable via `sdlc.docPath` (default `docs/`)
- Version pinning: `sdlc.templateVersion` in config
- Git: `git add` + `git commit` after doc output
- Confidentiality: Step 1 in every workflow warns user about LLM data sharing
- `__dirname` for template paths works correctly — `require(mcpToolsPath)` resolves to the package's own directory
- `installSkills({ domain: 'sdlc-workflows', sourceDir: absolutePath })` — sourceDir must be absolute, symlinks to `.opencode/skills/sdlc-workflows-<filename>.md`

```javascript
#!/usr/bin/env node
'use strict';

const path = require('path');
const fs = require('fs');
const { installSkills } = require('@andy-toolforge/core/lib/postinstall-skills');

// 1. Install skill files
installSkills({
  domain: 'sdlc-workflows',
  sourceDir: path.join(__dirname, 'skills'),
});

// 2. Generate version manifest
const pkg = require('./package.json');
const manifestDir = path.join(process.cwd(), '.opencode', 'manifests');
const manifestPath = path.join(manifestDir, 'sdlc-workflows.json');

fs.mkdirSync(manifestDir, { recursive: true });

// Scan templates directory
function scanTemplates(dir, prefix) {
  const results = [];
  if (!fs.existsSync(dir)) return results;
  for (const entry of fs.readdirSync(dir, { withFileTypes: true })) {
    const full = path.join(dir, entry.name);
    if (entry.isDirectory()) {
      results.push(...scanTemplates(full, prefix ? `${prefix}/${entry.name}` : entry.name));
    } else if (entry.isFile() && entry.name.endsWith('.md')) {
      const id = prefix ? `${prefix}/${entry.name.replace(/\.md$/, '')}` : entry.name.replace(/\.md$/, '');
      const standard = entry.name.includes('agile') ? 'agile' : 'itil';
      const type = full.includes('/standards/') ? 'standard' : 'flow';
      results.push({ id, name: entry.name.replace(/\.md$/, ''), standard, type });
    }
  }
  return results;
}

const manifest = {
  package: '@andy-toolforge/sdlc-workflows',
  installedVersion: pkg.version,
  installedAt: new Date().toISOString(),
  templates: scanTemplates(path.join(__dirname, 'templates'), ''),
};

fs.writeFileSync(manifestPath, JSON.stringify(manifest, null, 2));
console.log(`[sdlc-workflows] Manifest written to ${manifestPath}`);
```

- [ ] **Step 1: Create mcp-tools.js**

```javascript
'use strict';

/**
 * SDLC Workflows MCP plugin tools.
 * Auto-discovered by @andy-toolforge/mcp.
 *
 * Tools:
 *   sdlc_get_template       — Get template content by ID
 *   sdlc_list_templates     — List available templates
 *   sdlc_get_standard       — Get standard reference by ID
 *
 * Resolution order:
 *   1. Local override: .opencode/templates/<path> (project root)
 *   2. Package default: __dirname + '/templates/' + <path>
 */

const path = require('path');
const fs = require('fs');

const PACKAGE_TEMPLATES = path.resolve(__dirname, 'templates');

function readFileOrNull(filePath) {
  try { return fs.readFileSync(filePath, 'utf-8'); } catch { return null; }
}

function resolveTemplate(templateId) {
  // Normalize: strip .md extension if provided
  const id = templateId.replace(/\.md$/, '');
  const relativePath = id + '.md';

  // 1. Local override (project root's .opencode/templates/)
  const cwd = process.cwd();
  const localPath = path.join(cwd, '.opencode', 'templates', relativePath);
  const local = readFileOrNull(localPath);
  if (local) return { content: local, source: 'local-override' };

  // 2. Package default
  const pkgPath = path.join(PACKAGE_TEMPLATES, relativePath);
  const pkg = readFileOrNull(pkgPath);
  if (pkg) return { content: pkg, source: 'package' };

  return null;
}

const tools = [
  {
    definition: {
      name: 'sdlc_get_template',
      description: 'Get template content by ID (e.g. "prd/agile-prd" or "deploy/itil-runbook"). Checks local override first, falls back to package templates.',
      inputSchema: {
        type: 'object',
        properties: {
          templateId: { type: 'string', description: 'Template ID like "prd/agile-prd" or "deploy/itil-runbook"' },
        },
        required: ['templateId'],
      },
    },
    handler: async (_llm, args) => {
      const { templateId } = args || {};
      if (!templateId) {
        return { content: [{ type: 'text', text: 'Missing templateId' }], isError: true };
      }

      const result = resolveTemplate(templateId);
      if (!result) {
        return { content: [{ type: 'text', text: `Template not found: ${templateId}` }], isError: true };
      }

      return {
        content: [{
          type: 'text',
          text: JSON.stringify({
            content: result.content,
            metadata: { source: result.source, templateId },
          }),
        }],
      };
    },
  },
  {
    definition: {
      name: 'sdlc_list_templates',
      description: 'List available templates, optionally filtered by standard or flow.',
      inputSchema: {
        type: 'object',
        properties: {
          standard: { type: 'string', description: 'Filter by standard (agile, itil)' },
          flow: { type: 'string', description: 'Filter by flow (prd, deploy)' },
        },
      },
    },
    handler: async (_llm, args) => {
      // Read manifest if available, otherwise fallback to glob scan
      const manifestPath = path.join(process.cwd(), '.opencode', 'manifests', 'sdlc-workflows.json');
      let templates = [];

      const manifestRaw = readFileOrNull(manifestPath);
      if (manifestRaw) {
        try {
          templates = JSON.parse(manifestRaw).templates || [];
        } catch { /* fall through to fallback */ }
      }

      // Fallback: scan package templates directory
      if (templates.length === 0) {
        const { standard, flow } = args || {};
        // Minimal scan — read manifest from package
        const manifestPkgPath = path.join(PACKAGE_TEMPLATES, '.manifest.json');
        const pkgManifestRaw = readFileOrNull(manifestPkgPath);
        if (pkgManifestRaw) {
          try { templates = JSON.parse(pkgManifestRaw).templates || []; } catch {}
        }
        // Apply filters
        if (args?.standard) templates = templates.filter(t => t.standard === args.standard);
        if (args?.flow) templates = templates.filter(t => t.id.startsWith(args.flow));
      }

      const { standard, flow } = args || {};
      let filtered = templates;
      if (standard) filtered = filtered.filter(t => t.standard === standard);
      if (flow) filtered = filtered.filter(t => t.id.startsWith(flow));

      return {
        content: [{ type: 'text', text: JSON.stringify({ templates: filtered, source: manifestRaw ? 'manifest' : 'scan' }, null, 2) }],
      };
    },
  },
  {
    definition: {
      name: 'sdlc_get_standard',
      description: 'Get standard reference content by standard ID (e.g. "agile-scrum", "itil-sre").',
      inputSchema: {
        type: 'object',
        properties: {
          standardId: { type: 'string', description: 'Standard ID: "agile-scrum", "itil-sre"' },
        },
        required: ['standardId'],
      },
    },
    handler: async (_llm, args) => {
      const { standardId } = args || {};
      if (!standardId) {
        return { content: [{ type: 'text', text: 'Missing standardId' }], isError: true };
      }

      const result = resolveTemplate('standards/' + standardId);
      if (!result) {
        return { content: [{ type: 'text', text: `Standard not found: ${standardId}` }], isError: true };
      }

      return { content: [{ type: 'text', text: result.content }] };
    },
  },
];

module.exports = tools;
```

Khi user nói: "/project-onboard", "onboard dự án", "phân tích codebase", "audit dự án"
Hoặc chạy: `/project-onboard`

Khi nào dùng /project-onboard thay vì /project-init:
- Đã có code, cần AI understand codebase → /project-onboard
- Chưa có code, cần setup từ đầu → /project-init

## Input
- Codebase path (current directory)
- Optional: project description

## Output
- File: `.opencode/config.jsonc` (nếu chưa có)
- File: `AGENTS.md` (codebase conventions audit)
- File: SDLC audit report (docs/onboard-audit-<date>.md)

## Workflow
1. **Warn confidentiality**: "Thông tin bạn cung cấp sẽ được gửi lên LLM API. Skip nếu không muốn chia sẻ."
2. **Scan codebase**:
   - depth=3, exclude node_modules/.git/.next/dist
   - Focus: package.json, tsconfig, imports pattern, file structure
   - Detect: tech stack, framework, testing, linting, CI/CD
3. **SDLC audit**:
   - Scan docs/ cho SDLC documents (PRD, BRD, ADR, test plan, deploy)
   - Ghi chú: thiếu document nào, document nào outdated
   - Kiểm tra cross-ref: PRD feature → BRD? ADR → Test Plan?
4. **Gap analysis**: So sánh codebase complexity vs SDLC doc coverage
5. **Import existing docs**: Đọc SDLC docs có sẵn, parse YAML frontmatter
6. **Delta generation**: Sinh AGENTS.md rules dựa trên codebase conventions
7. **Get template**: Gọi MCP tool nếu available, fallback inline
8. **Output**: Ghi audit report + config + AGENTS.md
9. **Validate**: Kiểm tra cross-ref không mâu thuẫn
